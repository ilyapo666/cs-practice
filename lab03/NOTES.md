### Разница между git diff, git show и git log

- **git diff**: показывает разницу между рабочей директорией и индексом(или между коммитами)
Отвечает на вопрос: "Что изменилось, но еще не закоммичено?".
- **git show**: Показывает полную информацию о конкретном объекте Git (коммите, теге, дереве.) 
Для коммита показывает метаданные (автор, дата) и сам diff изменений.
- **git log**: Показывает историю коммитов в обратном хронологическом порядке (список коммитов с их кешами и сообщениями).

## Что нашли log -S и blame
- **log -S"def"**: Находит коммиты, в которых количество вхождений строки "def" изменилось (добавление или удаление).
Это позволяет найти, когда была добавлена та или иная функция.
- **blame**: Показывает построчно, какой коммит и какой автор последний раз меняли каждую конкретную строку файла. 
Помогает найти виновника изменений

### Чем отличается git restore от git restore --source=...

- `git restore <file>` — берёт содержимое из **HEAD** (последнего коммита)
  и записывает в рабочую директорию. Все незакоммиченные правки затираются.
- `git restore --source=<rev> <file>` — берёт содержимое из **явно указанного**
  коммита/ветки/тега (например, `HEAD~2`) и записывает в рабочую директорию.
  История коммитов при этом не меняется — просто во временном файле
  оказывается старая версия.

### Что произошло с моими правками

Я удалил несколько строк в calc.py, но не закоммитил их. После
`git restore lab03/calc.py` файл вернулся к состоянию последнего коммита —
мои удаления исчезли безвозвратно, потому что Git их нигде не сохранял.
После `git restore --source=HEAD~2 lab03/calc.py` в рабочей папке оказалась
старая версия файла (без умножения, т.к. HEAD~2 — коммит после сложения
и вычитания). Команда `git restore lab03/calc.py` вернула актуальную версию.

### Чем revert отличается от git reset --hard

- `git revert <commit>` — создаёт **новый коммит**, который отменяет изменения
  указанного коммита. История сохраняется: старый коммит остаётся, добавляется
  новый «отменяющий». Это безопасно для опубликованной истории.
- `git reset --hard <commit>` — **перемещает указатель ветки** на указанный
  коммит и затирает рабочую директорию и индекс. Коммиты, которые были после,
  «теряются» из истории ветки (хотя могут остаться в reflog). Если эти коммиты
  уже были отправлены на GitHub, у других разработчиков возникнут конфликты
  при попытке синхронизации, потому что история переписана.

### Почему в опубликованной истории безопаснее revert

Потому что `revert` не переписывает уже существующие коммиты, а лишь добавляет
новый. Другие разработчики могут просто сделать `git pull` и получить отмену.
`reset --hard` меняет историю, что требует force-push и ломает работу у тех,
кто уже скачал старую версию.

### Чем тег отличается от ветки

- **Тег** — это **неизменяемая метка** на конкретном коммите. Он не двигается
  при новых коммитах. Используется для обозначения версий (v1.0, v2.0 и т. д.).
- **Ветка** — это **подвижный указатель** на последний коммит в цепочке.
  При новых коммитах ветка автоматически перемещается вперёд. Используется
  для параллельной разработки.

Тег удобно использовать, чтобы через полгода найти конкретную версию
проекта и вернуться к ней.
